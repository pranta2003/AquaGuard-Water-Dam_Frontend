## Project Abstract

AquaGuard is a comprehensive, end-to-end Internet of Things (IoT) and Machine Learning cyber-physical system (CPS). Designed for real-time flood prediction and automated dam gate control, this project bridges the gap between physical water dynamics and low-latency software monitoring.

This repository contains the **Next.js Frontend Client**, which acts as the primary operational dashboard. It visualizes live telemetry from an ESP32 hardware network and displays predictive overflow countdowns generated by a backend Naive Bayes classifier.

## Hardware Prototype & IoT Architecture

At its core, AquaGuard is a hardware-driven system. Physical water levels dictate the entire data pipeline and automated physical responses.

**Core Hardware Components:**

* **Microcontroller:** ESP32 (Handles analog readings, localized hysteresis logic, and WiFi/Firebase data pushing).
* **Sensors:** 5x Analog Water Level Sensors (Positioned at staggered elevations inside the containment unit).
* **Actuators:** 2x Servo Motors (Simulating automated physical flood defense gates).
* **Alert System:** Active Buzzer (Hardware-level acoustic warning during critical overflow).
* **Power & Wiring:** Breadboard distribution, RTC (Real-Time Clock) modules, and direct analog routing.

## The Data Pipeline (How It Works)

To understand the scope of AquaGuard, here is the complete end-to-end data flow:

1. **Physical Layer:** Water enters the physical container, triggering the analog Water Level Sensors.
2. **IoT Layer:** The ESP32 processes the raw analog signals through strict hysteresis filters to prevent splash-triggered false positives. Validated state changes are pushed to the Firebase Realtime Database in milliseconds.
3. **Machine Learning Layer:** A Node.js backend listens to Firebase. Upon detecting a rapid surge, it spawns a Python script utilizing a **Naive Bayes classifier** (trained on historical flow-rate datasets) to predict the exact time until structural overflow.
4. **Presentation Layer (This Repository):** The Next.js frontend instantly syncs with Firebase, rendering the live sensor states, gate positions, and the pulsing ML-generated countdown timer.

## Core Software Features

* **Real-Time Telemetry Synchronization:** Live subscriptions to Firebase for millisecond-accurate updates from the hardware prototype.
* **Predictive Emergency UI:** Conditionally renders a high-visibility, pulsing countdown timer based on the Naive Bayes model's output, alerting users strictly during `WARNING` or `CRITICAL` states.
* **Actuator State Monitoring:** Tracks and visualizes the exact operational state (Open/Closed) of the physical servo gates.

## Local Development & Setup (Frontend)

### 1. Prerequisites

Ensure you have Node.js (v18.x or higher) and npm installed.

### 2. Environment Configuration

Create a `.env.local` file in the root directory and map your Firebase project credentials to securely connect the dashboard to the hardware data stream:

```env
NEXT_PUBLIC_FIREBASE_API_KEY="your_api_key"
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN="your_project_id.firebaseapp.com"
NEXT_PUBLIC_FIREBASE_DATABASE_URL="https://your_project_id-default-rtdb.firebaseio.com"
NEXT_PUBLIC_FIREBASE_PROJECT_ID="your_project_id"
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET="your_project_id.appspot.com"
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID="your_sender_id"
NEXT_PUBLIC_FIREBASE_APP_ID="your_app_id"

```

### 3. Installation & Execution

Clone the repository and install the required dependencies:

```bash
git clone https://github.com/yourusername/AquaGuard-Water-Dam_Frontend.git
cd AquaGuard-Water-Dam_Frontend
npm install

```

Launch the local development server:

```bash
npm run dev

```

Navigate to `http://localhost:3000` to view the active telemetry dashboard.
