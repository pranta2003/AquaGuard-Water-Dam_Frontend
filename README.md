## Project Abstract
AquaGuard is a cyber-physical system (CPS) designed for real-time flood prediction and automated dam gate control. This repository contains the **Next.js Frontend Client**, which serves as the primary telemetry visualization and emergency monitoring interface. It consumes live hardware data from an ESP32 microcontroller network and displays predictive countdowns generated by a backend Naive Bayes machine learning classifier, ensuring low-latency synchronization between physical water levels and software UI.

## Core Features & Capabilities

* **Real-Time Telemetry Synchronization:** Utilizes Firebase Realtime Database subscriptions to reflect millisecond-accurate state changes from five physical water level sensors (WLS).
* **Predictive Emergency UI:** Conditionally renders a high-visibility, pulsing countdown timer based on the Naive Bayes model's output, actively alerting users strictly during `WARNING` or `CRITICAL` surge states.
* **Actuator State Monitoring:** Tracks and visualizes the physical state (Open/Closed) of the automated servo flood gates responding to the hardware logic.
* **Responsive Architecture:** Built with Tailwind CSS to ensure the dashboard is accessible and maintainable across all operational control room screens and mobile devices.

## Technology Stack

* **Core Framework:** Next.js (React)
* **Styling:** Tailwind CSS, PostCSS
* **Data Layer:** Firebase Client SDK / Firebase Admin
* **Deployment Integration:** Vercel (CI/CD Pipeline)

## System Integration (Backend & ML)
*Note: This repository strictly handles the client-side presentation layer.* 
The frontend listens for payload updates generated by the centralized Node.js backend. When physical water dynamics cross critical thresholds, the backend spawns a Python script utilizing a Naive Bayes classifier to calculate the time-to-overflow. This prediction is pushed to Firebase and instantly reflected on this Next.js dashboard.

## Local Development & Setup

### 1. Prerequisites
Ensure you have Node.js (v18.x or higher) and npm installed.

### 2. Environment Configuration
Create a `.env.local` file in the root directory and map your Firebase project credentials to securely connect the dashboard to the hardware data stream:

```env
NEXT_PUBLIC_FIREBASE_API_KEY="your_api_key"
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN="your_project_id.firebaseapp.com"
NEXT_PUBLIC_FIREBASE_DATABASE_URL="https://your_project_id-default-rtdb.firebaseio.com"
NEXT_PUBLIC_FIREBASE_PROJECT_ID="your_project_id"
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET="your_project_id.appspot.com"
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID="your_sender_id"
